framing + completion-report reading migrated into /coo-startup, which runs every session.

whether a pointer resolves, not whether anything follows it. Written to memory as

### 4. BUG-64 (P1) — ci-wait.sh can PASS against the previous commit
Caught live during close-out. In branch mode, scripts/ci-wait.sh:79 infers its target SHA
from `gh run list --limit 1` — whatever the LATEST RUN is — then waits only for that SHA.
Run immediately after a merge, before GitHub registers the new commit's runs, it returns
PASS for the PREVIOUS commit. Observed: PASS @ 89ad005 seconds after merging #262 while
main was at 1b84557 with both workflows still in_progress.

P1 because this is the enforcement mechanism for CLAUDE.md's MANDATORY post-merge check —
the one thing standing between a squash-merge race and an unnoticed red main (BUG-24). It
FAILS OPEN, and it fails precisely when the documented procedure says to run it. Caught
only because the printed SHA was read rather than just the PASS line. Issue #263.
