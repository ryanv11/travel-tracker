### Process finding: OP-19 (new, raised and closed this session)
The Architect agent dispatched for OP-16 was not given `isolation: "worktree"` and
so shared this session's own working tree. Mid-task, a concurrent `git checkout` by
COO (creating the audit-archive branch) moved `HEAD` out from under the agent; its
commit landed on the COO's branch instead of its own. Caught via `git status`
before anything was pushed — relocated the commit to the correct branch
(`chore/op16-close`), pushed, opened the PR. No work was lost, but Ryan confirmed
explicitly this needs to be a standing rule, not a one-off recovery: "yeah agent
needs to be isolated and should have been working on his own branch." Fixed in
CLAUDE.md's Git workflow section — `isolation: "worktree"` is now mandatory for
every Agent-tool dispatch of a role agent doing git work; read-only dispatches
(research/review/investigation with no commits) are exempt. Also captured as a
feedback memory (`feedback_agent_dispatch_isolation.md`) so the reasoning survives
independent of CLAUDE.md.
