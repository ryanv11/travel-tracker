## THE THING MOST WORTH CARRYING FORWARD

**`gh run view <id> --log-failed` returned exit 0 and ZERO bytes on a genuinely failed
run.** Job logs live on a firewall-blocked Azure blob host; `gh` swallows the error. Every
agent in this project has been told to run it on any CI failure. "No output" reads as
"nothing failed."

It was documented in **10 places**, one of them gate-shaped — `/coo-startup`'s red-main
audit, i.e. the one check whose entire purpose is catching an unowned red main.

**`scripts/ci-wait.sh` was NOT touched and must not be.** It fails *closed* by design and
correctly reported the very failure that exposed this. The gate held; the diagnosis step
after it did not. That distinction is written into CLAUDE.md next to the replacement
command precisely so the next reader does not "fix" a script that was never broken.

## THE OTHER FINDING — and why it is P3, not critical

The OP-27 review found the allowlist is bypassable to **any Cloudflare-proxied origin** and
rated it CRITICAL. COO verified it live: `api.maptiler.com` is blocked by name (curl exit 7)
but returns **HTTP 301** pinned to an address `registry.npmjs.org` resolves to. Control
holds — `api.turso.tech` through the same edge fails TLS handshake, so this is *every
Cloudflare zone*, not everything.

**The PO then stated the actual threat model, which nobody had:** the container exists to
stop **CHANGES**, not reads; changes are restricted at API permissions; least privilege with
a case made for any access. Against that, F1 grants reads and no write capability — **low
severity**. The review had scored it against a containment model that was never the goal.

**But "low" is a CONDITION, not a property** — low *because* no credential exists for those
write APIs. That correction is the ADL author's, not the COO's; the COO's first tracker note
said "low severity" without the qualifier, which is exactly the propagation the author warned
about. If a Clerk or MapTiler credential is ever provisioned here, severity changes that day
and nothing re-triggers a review. That is why ADL-33 §4 now holds the standing condition —
a firewall comment is not read by whoever provisions a credential.

Best news in the whole finding, and it was buried: **`api.turso.tech` — the DB admin plane,
the one host where a write is catastrophic — is CloudFront-fronted with no allowlisted
neighbour. Its exclusion is EFFECTIVE.**

## Where the COO was wrong, four times

Recorded because the pattern is more useful than the instances.

1. **Fabricated a PO ruling.** Wrote "PO answer, supplied so you do not re-derive it: the PO
   tests in a browser on the host machine" into a brief. The PO had not said it. The
   inference was right, which is luck. An attributed decision is unarguable by design, so
   nobody downstream probes it — that makes it *worse* than an ordinary unverified claim.
   Caught on re-read; retracted in the issue and by message to the running agent.
   Memory: `feedback_never_attribute_an_inference_to_the_po`.
2. **A worthless probe, stated as evidence.** Told the QUAL-26 brief that
   `RAILWAY_GIT_COMMIT_SHA` "does not appear in staging's variable list." Railway's API
   enumerates only user-set variables — it lists NO platform-injected ones at all. The
   silence meant nothing. The agent caught it and built a baked-file fallback anyway.
3. **Reported hygiene debt that did not exist.** Told the PO there were 26 stale remote
   branches to prune. The GitHub API lists only `main` and `production`; the repo has
   `deleteBranchOnMerge: true`. They were stale *local* remote-tracking refs that had never
   been pruned. `git branch -r` is not a remote listing.
4. **Reached for the local fix before questioning the frame.** The opening proposal was an
   in-app workaround for the COO's own blindness — the fourth one-off handling of ENV-01's
   class in a single session. The PO caught it. **That is now five times on this project that
   the reframe came from the PO.**

Two of these were caught by agents, one by the PO, one by the COO. The review machinery is
earning its place, including against the COO.
