## THE MISTAKE THAT MATTERS MOST — read before trusting any deploy

**The shakedown froze staging for five commits and nothing went red.**

Railway's staging service sets `checkSuites: true` — it gates each deploy on that commit's
GitHub check suite. The shakedown shipped with a `push: branches: [main]` trigger. It runs
against the *already-deployed* app, so its failure means "the deployed build has a problem"
— but Railway read it as "this commit's checks failed" and **SKIPPED every deploy**.

Five commits never deployed, including the BUG-80 fix the PO was actively testing. Every PR
showed green. Main's CI showed green. The deploys were *skipped*, not *failed*, so there was
no alarm anywhere.

**Only the PO found it**, by reporting that a merged fix "still wasn't working" on staging.
Fixed in #391 (trigger reduced to `workflow_dispatch`). The comment in the workflow explains
why re-adding it re-creates the deadlock. Memory:
`feedback_post_deploy_checks_must_not_gate_deploys.md`.

**Standing check for the next session: if a deploy-gated check goes red, run
`list-deployments` and look for SKIPPED before assuming staging is current.**

## GE-17 (bundled city list) — WITHDRAWN. Do not reopen without a new argument.

Approved in principle 2026-08-02, withdrawn 2026-08-03 on PO direction. **All four of its
supporting arguments failed within two days, and nothing was built against it.**

1. *"Works offline"* — false. No service worker, no PWA manifest, no client cache; the table
   would have been server-side. The COO wrote this into the BRD from the PO's framing without
   probing it. Withdrawn in v3.15.
2. *"The only way to make the primary path testable"* — false. PO: *"we should be whitelisting
   services we need access to in local dev."* One line in `init-firewall.sh`. ADL-49 now covers
   it; ENV-01 reopened because accepting that constraint is what let it become an argument.
3. *"The only way to detect ambiguity"* — materially weakened; BUG-79's fix closed most of it
   with no dataset.
4. *"Covers the Scotland trip"* — **false, and never true.** The nine tail villages are absent
   from both candidate datasets. The PO typed Plockton into staging and **it worked**, via the
   geocoder — which also closed BUG-76's original question and ADL-48 §15.1's load-bearing
   unverified item in one action.

**GE-18 (attribution) survives independently** and is still owed — Natural Earth is bundled,
OSM is consumed, and ADL-43 §6.2 flagged ODbL before any city dataset was proposed.

Cost/benefit, recorded deliberately: four Architect documents and three OP-27 reviews, all
merged, none producing code. That is a spike working. It prevented a 17 MB dataset, a refresh
pipeline, a new table and a permanent maintenance obligation.

## BUG-75 — three rejected designs. Do not re-litigate the parts that held.

- **Rejected:** coordinate bucket (the widened index never fires — identity is decided in a
  SELECT before coordinates exist, and GE-12 requires creation to work offline, so this is
  structural); hashed `place_ref` (produced a wrong town, one user, no concurrency); the
  2026-08-04 carried-identity design (changes the key rows are *written* with, leaves the key
  they are *read* by unchanged).
- **HOLDS, and is new — do not re-derive:** `classifyCandidates`
  (`geocoding.service.ts:122-157`) decides ambiguity by counting distinct **regions**, not
  distinct **places**. Four Newports in GB-ENG return `ok` with an arbitrary `best`, **before
  any row exists**, on an empty table, with no index involved. Verified by executing the
  shipped function.
- **ALSO HOLDS:** fixing that alone does not fix BUG-75 — `findOrUpgradeCity` still decides
  which row a second user receives. Both halves are true simultaneously.

## The pattern worth carrying forward

**Four times on this thread the answer was a reframe rather than a better mechanism — and the
PO caught every one.** "Store a cities list in a table"; "we should whitelist the geocoder";
"I don't remember deciding to shorten place names"; and the `_app-*.js` filename that
identified a console error as Clerk's page rather than ours.

The OP-27 reviews are genuinely earning their place — they killed two designs that would have
shipped broken, one of them a migration the COO was one dispatch from sending. **But a
reviewer given "review this design" reviews the design, not the question behind it.** The
trigger written down after BUG-71 (scope growing across two consecutive rounds) fired here and
the COO stopped one round later than it should have.
