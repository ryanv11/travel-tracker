working theory (401 / mobile / Clerk token refresh) was WRONG and is superseded: literal

owner-gated routes in one action:

## 2. ADL-46 — approved and merged (the session's main output)
Access is determined by RESOURCE TIER × OPERATION, not role. The nine→fourteen decisions,
after five rounds of PO direction:
  - Categories/activities → per-user, lazy-seeded from global defaults (reuses ADL-28)
  - City creation splits from curation; any auth'd user creates via constrained find-or-create
  - Resolve-then-create: backend builds the row from the geocoder's canonical response
  - Containment: pending cities are creator-private, go global on resolution (self-maintaining)
  - Retry: recoverable errors retried w/ cap; a no-match is TERMINAL, never retried (needs
    chk_cities_geocode_status amended → 3rd table recreation)
  - Correction path: edit-with-re-resolve primary; discard-place fallback (no new API surface)
  - BUG-55 → backend geocoding proxy, not a widened CSP (User-Agent is a forbidden fetch header)
  - D13: city identity = (name COLLATE NOCASE, country_code, COALESCE(region_id,0)) — allows
    Springfield IL + Springfield MO; strictly more permissive so NO backfill/data risk
  - D14: multi-result → ASK (populate the region selector AddPlaceFlow already renders)
