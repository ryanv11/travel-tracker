## Process notes worth keeping

- **UAT earned its keep, twice over.** It validated the picker AND cracked BUG-76 — a bug three prior
  sessions could only hypothesise, because they couldn't reach Nominatim to verify it. The firewall's
  recovery was the unlock.
- **Stale-bundle red herring.** The picker "not firing" was a cached browser bundle after a mid-session
  staging redeploy (f7b36b8 → 4e77594). A hard refresh fixed it. When a deployed fix "isn't working,"
  check the deployed bundle (`curl` the /assets/*.js and grep for the new strings/logic) AND the browser
  cache before assuming a code bug. Verified the deployed bundle contained the correct logic before
  (correctly) concluding it was a cache issue.
- **Probe before recording.** I nearly recorded "the backend drops osm_id" as BUG-75's failure — held it
  pending the actual /api/geocode response, which showed osm_id present. The inference was wrong; not
  recording it saved a false root cause. Same discipline that verified BUG-76.
- **STATUS.md is generated from tracker.json.** A tracker status change makes STATUS.md stale and the
  `status:check` gate (correctly) fails CI. Run `npm run status` after any tracker status edit — /pre-push
  covers this; I skipped /pre-push once and the gate caught it on #414.
- **Double-trigger + strict branch protection** keeps leaving stale failed/cancelled duplicate runs that
  block merges even when required checks are green. Fix: rerun the stale run's failed jobs, or update the
  branch. `gh api --method PUT /repos/.../pulls/N/update-branch` cleanly re-syncs a behind PR server-side.
