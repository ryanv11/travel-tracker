### Process finding corrected mid-session: BUG-38 was wrong
Originally filed as a P2 (SQLite FK enforcement allegedly off by default, cascades
decorative). The BUG-32 backend brief independently proved this wrong while fixing a
real production 500 — FK enforcement is actually ON by default in `@libsql/client`
regardless of an explicit pragma. COO independently reproduced the same result.
BUG-38 closed as `not-a-bug`; the real underlying issue (items.trip_place_id had no
onDelete behaviour specified) was fixed in PR #166 via reassign-to-null rather than
cascade-delete, preserving logged items.

### OP-20: two more isolation near-misses, both contained
Same dispatch round, both caught before real harm:
1. Bare `git stash`/`git stash pop` collided across worktrees (refs/stash is a single
   ref shared by every linked worktree) — one agent's pop returned a different
