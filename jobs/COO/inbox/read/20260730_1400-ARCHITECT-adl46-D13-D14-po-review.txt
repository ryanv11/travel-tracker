ITEM 1 (city uniqueness) — FIXED IN SCOPE. D13: identity becomes
(name COLLATE NOCASE, country_code, COALESCE(region_id, 0)).
  - The COALESCE sentinel is the whole design. You flagged the NULL trap and you were right;
    0 is safe because regions.id is AUTOINCREMENT, which starts at 1. Verified, not assumed.
  - TWO PROPERTIES WORTH KNOWING, both good: the new key is STRICTLY MORE PERMISSIVE than the
    old one, so NO EXISTING ROW CAN VIOLATE IT — no backfill, no conflict handling, no data
    risk. And region_id MUST be NULL for non-region-tier countries, so the index degenerates
    to today's (name, country_code) exactly where the BUG-33 guarantee matters.
  - MIGRATION COST: ABSORBED by the cities recreation D10 already forces. No fourth migration.
  - THE RISK MOVED, and the briefs need to know: it is NOT the index, it is the LOOKUP.
    cities.ts:126-130 becomes three steps, and the middle one — wildcard-upgrade a region-less
    row rather than duplicating it — is the one that re-creates BUG-33 if omitted.

ITEM 2 (multi-result) — DECIDED: ASK. Zero candidates create pending, one is accepted, two or
more populate the region selector AddPlaceFlow ALREADY renders and UX-04 ALREADY fills in.
  WHY, since you gave me both options: (1) D13 changes the consequence of guessing — duplicates
  across regions are now legal, so a wrong auto-pick creates a plausible SECOND entry instead
  of colliding with the first; the failure got quieter at exactly the moment we made it
  possible. (2) It is the cheapest fix for item 3 — an entry never created needs no repair
  tool. (3) It keeps name, region and coordinates consistent, because all three come from one
  chosen candidate.
  THIS IS NOT THE PICKER I DECLINED LAST ROUND. The user is already being asked for the region;
  the control is on screen. Candidates populate its options instead of pre-selecting one. No
  new component. "Ambiguous" = more than one settlement-type candidate after the country
  constraint — deliberately no confidence threshold, because that is a number nobody can
  justify and everybody re-tunes. Auto-accept is documented as the first thing to cut.

  THE GENUINE GAP is narrower: the internally-wrong RESOLVED row. My deferred cleanup rule
