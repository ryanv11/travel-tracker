## What was delivered

**Root cause correction:** the "2 isolation failures" (`trips.spec.ts` search-filters,
detail-opens-on-click) were not database state leakage between spec files — they were
SEC-07's per-process rate limiter (300 req/min) exhausted by one long-lived backend
process serving all 36 specs sequentially. `deleteAllTrips` silently swallowed a failed
GET, which is what made the symptom look like leaked state. Fix: rate-limit `max` is now
conditional on `BYPASS_AUTH === 'true'` (unchanged 300/20 in every real deployment;
headroom only under a flag that's already fatal in `NODE_ENV=production`);
`deleteAllTrips` now throws loudly instead of swallowing failures. `security-spec.md`
updated in the same PR (document lifecycle).

**Selector hardening:** real `data-testid="trip-detail"` added to `TripDetail.tsx`'s root
— closes the known panel-scoping debt.

**CI job added** to `.github/workflows/ci.yml` (pinned action SHAs, chromium install,
report artifact on failure).
