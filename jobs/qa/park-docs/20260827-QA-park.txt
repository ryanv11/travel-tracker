  violations — under an explicit script-src (which server.ts always emits) a
  blocked eval() produces zero console output. Not a new defect; a pre-existing

  'ours-eval' scenario passes the old check and fails the new one.

  nor tsconfig.frontend.json, so npm run type:check:all never type-checks either
  Playwright suite. Pre-existing, outside this brief. Disposition: ESCALATED to
  COO in the completion report; needs a tracker entry.
[INFO — not a bug, a premise correction] The brief's diagnosis (eval under a
  script-src-less policy) cannot describe a context governed by our own CSP,
  because scriptSrc is set at the deployed commit 0dac8e8 and an explicit
  script-src suppresses the console message entirely. The violating context is a
  third party's, with its own policy. Disposition: recorded in the tech doc §3,
  marked UNVERIFIED against staging.

RESIDUAL RISK ON THE FIRST REAL RUN
Clerk spins a blob: worker (see server.ts's worker-src comment). A blob: worker
inherits the creating page's origin, so if that worker violates our policy it is
attributed to US and the check goes red. That is deliberate (fail closed on
ambiguity) and the output will name exactly what it is — but it means a red first
run is a plausible outcome that should be read, not assumed to be a regression.
