3. THE THREE DECISIONS A SUCCESSOR MOST NEEDS TO KNOW
═══════════════════════════════════════════════════════════════════════════
(a) THE MOCK BOUNDARY MOVED, ON PURPOSE.
    Every pre-existing AddPlaceFlow suite mocks hooks/useCities wholesale.
    These suites mock utils/apiClient instead. Three reasons, in full in
    fixtures/adl56Harness.tsx's header: D8/B1 is a claim about GET /api/geocode
    EGRESS (a useCities stub measures the wrong event); ADL-56 §3b(6)
    recommends replacing the imperative lookupCityCountry with a query-keyed
    hook, and a stub of it would go red on that refactor for non-behavioural
    reasons; and a useCities stub erases the `status` discriminator D5's
    S4-vs-S5 routing depends on. Do NOT "simplify" these back to a useCities
    mock — it silently removes the contract.

(b) THE RED BAR IS CARRIED AS describe.skip + [S1][RED-BAR], NOT AS RED CI.
    Repo convention, established by the GE-19/ADL-55 bar. The implementer
    un-skips each block as they green it, so a weakened assertion shows in
    that diff. Every block was verified red by running throwaway sibling
    *.redcheck.test.* copies with describe.skip rewritten to describe — the
    committed file was never mutated to obtain the evidence, and no git stash
    was used (OP-20: refs/stash is shared across worktrees).

(c) ASSERTIONS THAT ARE GREEN TODAY LIVE IN [S1][GUARD] BLOCKS, UN-SKIPPED.
    Parking a green test inside a red block is how a red bar becomes
    decorative. Seven guards are split out; the sharpest is the §6b(1)
    mergeIntoWinner exclusion, which is green today only because no backfill
    exists yet and is the assertion a careless D4 implementation will break.

4. THE INTERIM TRIPWIRES — DO NOT DELETE CASUALLY
═══════════════════════════════════════════════════════════════════════════
Two un-skipped, currently-GREEN tests encode the GE-21 Slice-1 -> Slice-2
interim:
  cities.adl56-s2-name-path.test.ts  ->  "[INTERIM][GE-21 Slice 1->2] the
      backend name path still resolves a same-region ambiguity"
  decideCityDisambiguation.adl56-s2.test.ts  ->  "[INTERIM][GE-21 Slice 1->2]
      the frontend still shows a picker for the two Melbourne granularities"

WHEN EITHER TURNS RED, THAT IS SLICE 2 WORKING. The correct response is:
delete the tripwire block, un-skip its [S2] twin, and re-stamp the interim
closed in ADL-56 §10a and the BRD v3.22 GE-21 row. The WRONG response is to
relax the assertion. Both blocks carry that instruction inline.

Rationale (this is the part that is easy to lose): a skipped marker records an
intention; a green test that will break creates an obligation. Vitest's default
reporter prints only a skip COUNT, never the names, so skipped markers alone
cannot make an interim visible on a green board.

7. HOW TO RE-VERIFY A RED WITHOUT BREAKING ANYTHING
═══════════════════════════════════════════════════════════════════════════
  sed -e 's/describe\.skip(/describe(/g' <file> > <file-with-.redcheck.test.>
  npx vitest run --config vitest.config.{frontend|backend}.ts <tmp>
