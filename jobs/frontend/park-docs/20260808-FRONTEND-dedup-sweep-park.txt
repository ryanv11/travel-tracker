4. QUAL-31 — components/shared/ModalOverlay.tsx (new), adopted at 8 sites
   across 7 files: ConfirmDialog (had its own bundled copy — unified),
   TripForm, ItemForm, PlaceDateForm, ChangeCityModal, AddPlaceFlow (3
   separate early-return branches: creationStatusMessage, placeWarnings,
   the main add-place form), CarryForwardModal.
   Design decisions worth flagging:
   - z-index goes through `style={{ zIndex }}`, NOT a `z-[${n}]` Tailwind
     class. Tailwind's JIT content-scanner needs a complete, static class
     string in source to generate the CSS rule; a template-literal
     interpolation defeats that scanner and the site would silently lose
     its stacking order in a production build — a real, easy-to-miss
     regression class this sidesteps entirely. Confirmed there's no
     tailwind.config.js (Tailwind v4, CSS-based @theme config per
     theme-waypoint.css) so this isn't a config-level content-glob issue,
     it's inherent to how JIT scanning works regardless of config style.
   - CarryForwardModal was the one outlier: inline React.CSSProperties
     instead of Tailwind, AND the one site with genuinely different
     behavior — no backdrop-click-dismiss at all (only its own Skip button
     or the post-success setTimeout). Preserved via
     `closeOnBackdropClick={false}` (no onClose passed at all) plus a new
     `panelStyle` prop carrying its exact original inline styles verbatim —
     specifically to avoid silently swapping its custom box-shadow for
     Tailwind's shadow-2xl (subtly different blur/spread values). A comment
     at the call site explains this is deliberate, not an oversight.
   - Deliberately did NOT add ESC-key handling, a focus trap, or
     role="dialog"/aria-modal to the shared component. None of the 8
     original sites had any of these — adding them here would be new
     behavior introduced by what's supposed to be a behavior-preserving
     refactor. Flagging as a good candidate for a future UX-driven
     accessibility pass across all 8 sites at once (their consistency is
     exactly what this extraction now makes cheap), not built here since
     it wasn't asked for and would need a UX call on focus-trap/ESC
     semantics per site.
   Verified all 8 sites still type-check and the full frontend suite (which
   exercises TripForm/ItemForm/ChangeCityModal/AddPlaceFlow/CarryForwardModal
   indirectly through their existing integration tests) stayed green.
