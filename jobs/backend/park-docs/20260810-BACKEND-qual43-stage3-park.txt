================================================================

services/shading.service.ts :169, :209, :247, :291 now compose
scopeToUser(trips, userId). A COMPOSITION, not a relocation — the queries
stay in the service.

  :169  getTripCountriesStats     .where(...)         -> scopeToUser
  :209  getAllCountryShading      leftJoin ON-clause  -> scopeToUser
  :247  getCountryShading         leftJoin ON-clause  -> scopeToUser
  :291  getRegionShading          leftJoin ON-clause  -> scopeToUser

THE LOAD-BEARING DETAIL, documented in the file header so it survives a
future edit: three of the four sit in a LEFT JOIN's ON-clause, not a WHERE.
These are aggregate queries driven FROM countries / FROM regions, so a
country or region with no matching trip MUST still produce a row (state
never_visited). Moving the ownership predicate out of the ON-clause and into
a WHERE would turn each LEFT JOIN into an effective INNER JOIN and silently
drop every unvisited unit from the map — a much larger visible regression
than a scoping bug, but silent in a naive refactor. Join semantics preserved
exactly; only the predicate's spelling changed.

F3 FOOTGUN (ADL-53 §6): checked and does not apply here. None of the four is
a $dynamic() or multi-.where() builder; each has at most one terminal
.where(). The two that DO have a .where() (:248 countries, :292 regions) carry
a country/region filter there, with ownership in the join — untouched.

OP-06: the four sites are the only ownership expressions in this file, all
still present, all still on trips. No route gained or lost auth middleware.

CHECK 2 — `getDb` in src/backend/routes/** (warn-only). AUTHORED here. No
ADL-53 stage created it; Stage 5 only "flips" it, and cannot flip what does
not exist. Added as a second check in the same script, not a second script.

  MENTIONS-vs-CALL-SITES DECISION: counts MENTIONS of the literal string.
  Reasoning, recorded because Stage 5 inherits it:
    - Counting `const db = getDb()` call sites is EVADABLE and forfeits the
      guard's whole claim — `const d = getDb()`, `const { select } = getDb()`,
      or passing getDb as a value all sail past. Door-completeness is a
      property of the STRING (getDb is the only exported ORM accessor,
      independently verified by ADL-53's fresh-eyes review), and the string is
      what makes this a one-line fail-closed grep rather than an AST rule.
    - The false positives are cheap and self-clearing: a comment is reworded
      (OP-30) and the ReturnType<typeof getDb> type refs leave routes/ anyway
      when Stage 2 moves the helpers that use them.
    - It matches the sibling check, which also matches text, not syntax.
  To keep that strict-but-honest, each match is CLASSIFIED in the output
  (call-site / type-ref / import / comment / mention) so Stage 5 can see at a
  glance what is real relocation work and what is a rewording.
