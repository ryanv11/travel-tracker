7. NEW CROSS-CUTTING PROPERTY (§10.8) — APPLIES TO ADL-33's EXISTING ENTRIES TOO
--------------------------------------------------------------------------------
init-firewall.sh builds an ipset of IP ADDRESSES and matches on destination address
(lines 83, 160-168). It does NOT filter by hostname or SNI. Adding a host therefore grants
every service reachable at the addresses that host resolved to at container start.

For a dedicated IP that is one service. For Fastly anycast (Nominatim), Cloudflare
(MapTiler), or Railway's edge (both app domains) it is not. This changes no verdict — the
extra reach is real and small — but it is the correct unit of "what does one more line
cost": more than one host, and the same amount for every line.

Durable fix (SNI-aware egress proxy) named and explicitly NOT proposed; far larger than
anything this project needs today. Recorded so the next person to notice finds it considered.

8. METHOD — THE TRAP, AND THE PROBE APPARATUS
--------------------------------------------------------------------------------
THE TRAP, first because it disqualifies the obvious probe: DNS/UDP-53 stays OPEN through
lockdown (init-firewall.sh:52-53) and MUST — the script's own dig at line 153 depends on it.
So resolution succeeds for every host on the internet, blocked or not. A successful dig
proves nothing and is used nowhere below as evidence of reachability.

  Probe A  real TCP/TLS attempt, with allowed AND blocked controls in the same pass
           (api.github.com 200 / registry.npmjs.org 200 / example.com fails in 45 ms).
           TIMING is a second signal: blocked = tens of ms PER ADDRESS via ICMP
           admin-prohibited; a dead upstream black-holes and times out.
  Probe B  read the allowlist config — BOTH the repo copy and /usr/local/bin/init-firewall.sh
           (diff'd: identical on this branch; they are different files and could diverge).
  Probe C  run the real operation (gh run download, gh api .../logs). Strongest of the three,
           and the one that turned the artifact question from a guess into a finding.
  Probe D  address-space characterisation via dig — mapping WHAT WOULD BE PINNED, not
           reachability. Distinct job, stated as such.

BLIND SPOT worth carrying forward: could NOT read the live ipset. `ipset list` needs root and
sudo here is restricted to init-firewall.sh only (/etc/sudoers.d/node-firewall). Every
"blocked" row's probe B is the SCRIPT, not the running set. Probe A is the mitigation — it
tests live kernel state, and A and B agree in all 13 cases.
