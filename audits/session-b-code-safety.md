## Codebase survey

Full-stack TypeScript monorepo: Express 5 backend (`src/backend/` — routes → services/repositories → Drizzle ORM → libSQL/SQLite) and React 18 + Vite frontend (`src/frontend/` — pages → components → TanStack Query hooks → `apiClient`). Schema lives in one file (`schema.ts`, 21 tables) with generated SQL migrations (`0000`–`0007`). Auth is Clerk JWTs verified backend-side via jose/JWKS (`middleware/auth.ts`), with a `BYPASS_AUTH` escape hatch for CI/local; `requireAuth` is applied globally at `/api/*` in `server.ts`, owner-only routes add `requireOwner`. Test surface: backend unit tests (Vitest + supertest against `server-test-app.ts`), contract tests (`tests/contract/` against a live server), frontend unit tests, Playwright E2E (not in CI). Gates: CI (biome, typecheck, backend, frontend, contract) + security workflow (npm audit, Gitleaks, Semgrep incl. custom rules in `.semgrep/security.yml`); local PostToolUse hooks run typecheck and a drift ledger on every Write/Edit. Overall state: the code is consistently commented and conventionally strong, but several load-bearing rules exist only in comments/CLAUDE.md, and a few high-traffic comments are stale in dangerous directions (details below).

## Invariants inventory (Audit 5)

Format per item: **Invariant** — where it's currently enforced/assumed · what breaks if violated · proposed disposition. (CLAUDE.md = prose rule for agents; CHECK = automated gate.)

### Area 1 — DB layer

1. **Schema changes go through `db:generate` + `db:migrate`; never `drizzle-kit push`.** Enforced: script removed from package.json, CLAUDE.md rule, ADL-15. **Gap:** nothing stops `npx drizzle-kit push` run directly — it would bypass the patched migration path and can corrupt/desync the migrations journal. Breaks: dev.db diverges from `migrations/`, next `db:migrate` fails or double-applies. **Disposition:** already in CLAUDE.md; add CHECK — a PreToolUse hook rejecting Bash commands matching `drizzle-kit\s+push|db:push`.
2. **`drizzle-kit` must stay pinned at exactly `0.31.9`.** Enforced: exact pin in package.json (no `^`) + `patch-package` fails `npm install` loudly on version mismatch. Breaks: the four patched SQLite bugs return (infinite loops in generate). **Disposition:** adequately automated already — record here for completeness. The rationale lives in ADL-15 + agent memory; fine.
3. **Every user-data table must have `user_id` `.notNull().references(() => users.id)`, an index on it, and all queries scoped to `req.user.id`** (ADL-16/HC-07c; currently true of trips, trip_places, items). Enforced: CLAUDE.md backend-brief security checklist (prose), access-matrix contract tests (only for *existing* routes), Semgrep rule 2 — **which is a TODO stub, not a rule** (`.semgrep/security.yml` rule 2 is entirely commented out; see Area-7 finding). Breaks: cross-user data leak — the exact class OP-06 found (shading aggregate leak, HC-03). **Disposition:** both. Keep the CLAUDE.md checklist; add CHECK — a schema test asserting every table that references `users.id` does so NOT NULL, plus the promised GitHub issue for a workable Semgrep/taint rule (the yml says "raise a GitHub issue to revisit" — none found: `gh issue list` shows no such issue).
4. **`map_shading_config` and `companions` are deliberately NOT user-scoped yet** (ADL-28: decided, not implemented). A conscientious newcomer applying invariant 3 everywhere would "fix" them and jump the migration queue. Enforced: only by reading ADL-28. Breaks: an unplanned migration + conflicts with the ADL-28 design when it lands. **Disposition:** CLAUDE.md one-liner or schema comment on both tables: "global by design until ADL-28 is implemented."
5. **Carry-forward pairing: `is_carried_forward = 1` ⇔ `carried_from_item_id IS NOT NULL`.** Enforced: comment in schema (`schema.ts:396-398` "BACKEND must enforce") + whatever the items service does; no DB CHECK. Breaks: orphaned carry-forward flags corrupt IT-07 lineage queries (partial index `idx_items_carried` only covers non-null FK rows). **Disposition:** CHECK — a SQLite `CHECK ((is_carried_forward = 0) OR (carried_from_item_id IS NOT NULL))` is mechanically expressible; propose adding in the next schema migration. Until then, a contract/unit test asserting the API can't produce the mismatched state.
6. **`trips.start_date <= trips.end_date`** enforced only in Zod (`schema.ts:203-204` says BACKEND must validate; DB cannot). Breaks: date-range filtering and shading state computation misbehave quietly. **Disposition:** covered if Zod schema has the refinement (verified: it does — `trips.schemas.ts`); add one repository-level test so a future "simplify the Zod schema" change fails loudly.
7. **`trip_countries` is derived data that must stay in sync with `trip_places`** (stored denormalisation, ADL-23). Enforced: route code only — whoever adds/removes places must update trip_countries. Breaks: map shading shows countries the user never visited (or misses ones they did) with no error anywhere. **Disposition:** CHECK — a contract test that creates/deletes places and asserts trip_countries follows; consider a periodic consistency assertion in tests (`SELECT` mismatch between the two must be empty).
